# Claude Code / Codex 共通ハーネス

ユーザー承認済みの方針: 同一リポジトリ、別worktree、品質基準の共有、実行設定の分離。

## 実行経路

既存の対話セッション・hookは維持する。追加する正本は Node.js 24 のローカルCLI
`node scripts/harness/run.mjs <plan.json> --engine codex|claude`。
承認したJSON計画の依存グラフを実行し、子プロセスとして `codex exec` / `claude -p`
を標準入出力で呼ぶ。MCPや新しいクラウドDBは追加しない。モデル指定はCLI既定を維持。
認証は各CLIの既存ログインを使用し、資格情報を計画やログに書かない。

## 共通契約

- 入力: 名前、依存ノード、役割プロンプト、読み取り/書き込み区分、必須チェックコマンド。
- 独立した読み取りノードのみ指定並列数で実行。書き込み・チェックは全体で直列化する。
- 結果: pass/fail/blocked と空でない説明。非ゼロ終了・形式不正は成功にしない。
- ノードの失敗で後続を停止する。同じ失敗の自動再送はしない。
- 上限つきの再実行は人間が原因・次の仮説を書いた再試行記録を渡した場合だけ許す。
- 依存グラフの循環・未知依存・重複ID・無制限時間は実行前に拒否する。
- 計画変更と作業ツリー変更で古い結果を再利用しない。再試行は全グラフを実行する。
- 書き込みは専用worktree、engineに一致するブランチ、明示的な `--allow-write` が必要。
- すべてのrunはworktree単位の排他ロックを取る。同じタスクIDは共通Git領域でも排他。
- 状態と証跡はGit管理外の共通Git領域内に engine/run 単位で保存する。
- 成功表現は `verified_local` に限定。GitHub CI成功・PR統合とは区別する。

## 範囲と受け入れ条件

| 分類 | 内容 |
| --- | --- |
| 今回実施 | CLI・両engineアダプター・依存順/並列上限・実終了コード・排他・有限再試行・タイムアウト・回帰テスト・共通運用文書・Codex手順の並列枠修正 |
| 今回実施 | テストは一時Gitリポジトリと実子プロセスを使用。失敗/循環/同時起動/改変/上限の否定テストを含め、既存hooks-testから実行する |
| ユーザーまたは外部環境の準備待ち | 両CLIの認証と利用枠、project hookの信頼。実機検証で不足が判明した経路のみ未検証とする |
| 今回実施 | 読み取り専用の小さな計画で両CLIの実応答を確認し、PRの対象commitでGitHub CIを確認する |
| 後続の別タスク | 医療在庫の全役割・全評価fixtureの移植、過去課題を用いたモデル間精度比較、他2リポジトリへの展開 |

## 境界

実行ロックはこのCLIを使う処理の協調排他であり、手動セッションをOSレベルで隔離しない。
既存hookの実行記録を成功証拠として流用しない。チェックはrunnerが直接起動する。
DB・本番更新・デプロイは計画に自動追加しない。共有DB/ポートの利用は実行前に隔離か
直列化を決める。読み取り側もCLI設定やhookによる外部副作用まで保証するものではない。
